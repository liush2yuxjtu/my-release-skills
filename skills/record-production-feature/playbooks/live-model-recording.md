# Live model feature recording

用于通过真实产品 UI 录制依赖 LLM API 的功能。模型实际生成响应、选择工具；操作脚本只负责用户输入、观察、取景与捕获。依赖本技能原有版本、主机、预演、媒体和视觉门禁。

## 1. 定义成功条件与预算

1. 写一句用户结果，列出业务不变量与最终可见证据。例如“字幕生成后可编辑、时间范围有效”，而不是固定字幕全文；Agent 修复任务检查实际文件 diff、原有测试与清理结果，不预写诊断或工具路线。
2. 固定产品 commit/运行版本、surface、模型 provider 与请求 model、已知实际 model、系统/用户 prompt、工具 schema、演示输入及起始状态。记录参数和内容指纹；seed/temperature 只记录实际值，不保证确定性。
3. 从 [live 模板](../assets/model-execution.live.template.json) 建立 `evidence/model-execution.json`。录前填正数的最大 take 数、整轮 live 请求数（包括预演与传输重试）、单请求和单 take 超时；费用可观测时另设费用上限，未知时记 unknown 并以请求/时间上限控制。沿用已有调用、内容披露和费用授权。
4. 使用独立演示项目和无敏感输入。凭据留在已有授权环境；缺少凭据/网络/依赖时标 `blocked`，不回退 scripted。此文档的更新本身不授权新的付费调用。

## 2. 预演并恢复起始状态

- 先验证真实 UI、登录、驱动、状态读取、录制器和 API adapter，按既有规则运行项目 `/verify` 与适用测试。直接 ping API 只验证连通性。
- 预演通过产品执行一次真实流程，记录调用与业务断言。给长调用设置可取消的状态等待，并确认失败、超时与取消在产品中的实际表现。
- 预演和正式录制使用独立 run/take；恢复同一演示输入与项目快照，清理本任务造成的文件/TODO 状态，重新确认界面。不得预填 Assistant 回复、TODO、工具结果或已完成任务来代替模型执行。
- 模型允许选不同的有效工具路径。下一步基于当前 UI 与实际业务状态，选择器定位稳定角色/区域，不能因文案偏离预稿而篡改输出。业务断言改变时更新 brief，再重新预演。

## 3. 录制真实执行

1. 在触发请求前开始完整 GT 捕获与单调时间 marker。
2. 展示真实用户输入和提交动作，记录 `request-start`、`first-response`、每个 `tool-start/tool-end`、任务终态与 `result-readable`。每条请求关联本 run、顺序、request/response ID（服务提供时）、状态、耗时、usage 及对应工具事件；不依赖汇总布尔值证明 live。
3. 等待产品终态并验证业务结果。固定停顿只用于鼠标节奏、可读停留，不用于判断模型是否完成；有响应文本、HTTP 200 或 spinner 消失都不足以单独判定成功。
4. 保留 streaming 中间态、真实等待和错误。按真实结果调整镜头，结果稳定可读至少 3 秒后结束捕获。多步 Agent 同时验证真实工具日志、文件/任务状态和模型最终结论一致。
5. 结束后写原片哈希、调用数与 marker，完成固定时刻抽帧及 timing 核验，再判 keep/discard。

## 4. 失败与重试

- 为每个 take 立即写 `runs/takes.log`：phase、take id、时间、live 请求数、usage/可知费用、结果、失败原因、原片/日志/抽帧路径。预演失败也计入整轮调用预算；录制中途失败保留实际捕获部分并标 incomplete，不称完整 GT。
- 只对确认为临时网络、429 或服务端故障的请求按服务提示有界退避。先确认原请求是否仍运行/已产生副作用；使用产品已有重试/幂等机制，不重复点击制造并行任务。预算计入每次真实尝试。
- 内容或业务结果失败记为失败；查明原因后恢复初态再开新 take。可从记录完整的成功 take 选片，但不能用一次选片结论宣称可靠率。禁止无限重试、隐藏失败、换预设答案，或把不同 take 的输入和结果拼成一次执行。
- 达到预算/超时即停止本轮新增调用，按产品取消本任务并保留回执。没有成功 take 就交付实际阻塞。若已有合格真实 capture，可另建显式 replay run，执行 [captured replay playbook](captured-model-replay.md)，不在失败 take 中偷换模式。

## 5. 选片与交付

- 优先从成功原片生成派生物；GT 与完整 MP4 保留真实等待。默认 GIF 取连续 8 秒，可聚焦结果出现及应用；不足以说明全过程时关联完整视频，不补造结果。若需要实际最终帧的阅读停留，按[完整视频交付契约](../references/delivered-video-verification.md)显式记录 editorial hold，源证据时长与交付阅读时长分开，不计作运行证明。
- 若另需压缩等待，用支持可追溯时间线的实际编辑器另做版本并标明加速；不得声称当前连续截取脚本支持任意剪接。
- `current_live_e2e=pass` 仅在本 take 的产品流程、业务断言和调用证据都通过时填写；API 连通、协议/单元测试和另一次运行不能替代。模型验收通过也不自动意味着媒体视觉或发布验收通过。
- 在 feature、QA 和 handoff 关联同一份模型证据与原片哈希，调用数从逐条日志计算并核对汇总。公开只交付获准的脱敏摘要与完整性校验，原始请求 trace 留在授权归档。

通过条件：真实来源、业务结果、预算/失败记录、take 与模型证据关联、原片/画面和原有交付门禁全部通过。没有实际运行时只可交付计划，不能填 pass。
